# 2022 ICM Problem D：完整建模思路

## 1. 研究定位与总体框架

ICM Corporation 是赛题设定的案例公司。题目仅提供港口运营情景、日常处理的数据类型以及人员、技术和流程方面的管理问题，没有提供 ICM 的真实数值数据。因此，本研究的任务不是估计 ICM 当前的真实成熟度，而是设计一套能够在部署后收集数据、处理数据、计算指标、评价成熟度并制定改进方案的完整系统。

比赛阶段使用公开资料约束指标定义和参数范围，并使用明确标注的情景数据演示模型。模拟结果只说明模型在给定假设下如何运行，不代表 ICM 的实际经营状态。

总体流程为：

\[
\boxed{
\text{业务需求解析}
\rightarrow \text{指标识别与筛选}
\rightarrow \text{数据采集}
\rightarrow \text{数据处理}
\rightarrow \text{KPI与时序量化}
\rightarrow \text{能力状态估计}
\rightarrow \text{成熟度评价}
\rightarrow \text{资源优化}
\rightarrow \text{持续监测}
}
\]

整套方法遵循四条原则：

1. 所有指标和参数必须具有明确来源，包括赛题业务要求、公开文献、行业标准、统计估计或有记录的专家咨询。
2. 专家意见用于补充业务机制、适用条件和可行范围，不直接替代可观测数据。
3. 每个核心模型单独分析两项可能造成输出失真的现实因素，并设置专属检验。
4. 数据、规则和参数均保留来源、版本与适用范围，情景假设不得冒充统计估计。

## 2. 研究对象、符号与数据边界

将 ICM 的数据与分析系统划分为人员、技术、流程三个基础维度，并增加端到端业务协同层：

- 人员（People）：岗位技能、人才覆盖、培训效果、招聘或外包能力。
- 技术（Technology）：系统可靠性、数据交换、处理延迟、恢复能力和扩展能力。
- 流程（Process）：数据质量、责任归属、元数据、访问权限和生命周期管理。
- 协同（Integration）：人员、技术和流程能否共同支持船舶、海关、堆场、卡车及铁路之间的数据流转。

主要符号如下：

| 符号 | 含义 |
|---|---|
| \(i\) | 指标编号 |
| \(d\) | 能力维度，\(d\in\{P,T,R\}\) |
| \(b\) | 部门、港区或业务单元 |
| \(t\) | 统计时期 |
| \(h\) | 抽样层，如岗位、班次或货种 |
| \(k\) | 端到端业务链 |
| \(j\) | 改进项目 |
| \(D^{\mathrm{ref}}\) | 文献、标准和公开基准资料 |
| \(D^{\mathrm{obs}}\) | 企业部署后采集的实际观测 |
| \(D^{\mathrm{sim}}\) | 用于演示和检验的情景数据 |

必须在数据表中标明数据类别：

\[
D=\{D^{\mathrm{ref}},D^{\mathrm{obs}},D^{\mathrm{sim}}\}.
\]

外部基准不能直接视为 ICM 观测值；模拟参数必须标记为情景假设。

## 3. 业务需求解析

根据赛题所述运营流程，构建需求集合：

\[
\mathcal G=\{
\text{岗位能力、人才配置、技术可靠性、系统互通、数据质量、}
\text{访问治理、元数据、生命周期、端到端协同}
\}.
\]

建立“业务问题—指标—原始字段—管理行动”映射。例如：

| 业务问题 | 指标 | 原始记录 | 可采取的行动 |
|---|---|---|---|
| 不同系统中的集装箱状态冲突 | 跨系统一致率 | 集装箱编号、系统状态、更新时间 | 统一数据标准与接口规则 |
| 员工培训是否有效 | 培训后能力保持 | 培训日期、前测、后测和延后测试 | 调整课程、对象和培训周期 |
| 数据访问审批过慢 | 访问审批周期 | 申请、批准、拒绝及完成时间 | 优化权限流程与自动审批 |
| 数据问题长期未关闭 | 问题闭环时长 | 工单创建、处理、复核和关闭时间 | 明确责任人与升级规则 |

每项指标只有同时满足“对应明确业务需求、可以观测、能够引导行动”时才进入候选池。

## 4. 指标识别与筛选模型

### 4.1 候选指标识别

候选指标由四类证据产生：赛题业务描述、公开文献、适用行业标准、结构化专家咨询。没有实际开展的专家咨询只能作为部署方案，不能写成已获得结果。

初始指标池如下：

| 编号 | 维度 | 指标 | 操作性定义 | 主要数据来源 |
|---|---|---|---|---|
| P1 | 人员 | 岗位技能达标率 | 达到岗位实操要求的人数/有效考核人数 | 岗位标准、实操测试 |
| P2 | 人员 | 关键技能覆盖率 | 已配置合格人员的必需岗位—技能项/全部必需项 | 岗位清单、资格与排班 |
| P3 | 人员 | 培训后能力保持 | 培训后多期实操表现的时序量化值 | 培训及跟踪测试 |
| P4 | 人员 | 人才缺口填补时间 | 需求批准至合格人员实际到岗的时长 | 招聘、调配、外包记录 |
| T1 | 技术 | 业务要求时段可用率 | 能提供规定服务的时间/要求服务时间 | 服务计划、故障日志 |
| T2 | 技术 | 数据交换成功率 | 正确完成交付的逻辑交易数/应交付交易数 | 接口与业务日志 |
| T3 | 技术 | 数据交付延迟 | 要求可用时间至实际可用时间的差值 | 源端与接收端时间戳 |
| T4 | 技术 | 恢复要求达成率 | 达到适用恢复要求的演练数/有效演练数 | 备份恢复演练 |
| R1 | 流程 | 关键字段完整率 | 已填且可用的必需字段数/应填字段数 | 数据规则、业务记录 |
| R2 | 流程 | 抽样数据准确率 | 与独立依据一致的抽查项/可核验抽查项 | 原始凭据、审计 |
| R3 | 流程 | 跨系统一致率 | 满足一致性规则的匹配记录/应匹配记录 | 关联记录 |
| R4 | 流程 | 数据责任覆盖率 | 有有效责任人的适用数据资产/全部适用资产 | 数据目录、责任清单 |
| R5 | 流程 | 元数据符合率 | 满足元数据要求的资产/被检查资产 | 元数据目录 |
| R6 | 流程 | 访问和生命周期合规率 | 满足审批、保留和处置规则的项目/适用项目 | 权限与审计记录 |
| C1 | 协同 | 数据问题闭环时长 | 问题登记至确认修复的时长 | 工单、复核记录 |
| C2 | 协同 | 端到端数据服务成功率 | 按时且无重大数据错误完成的业务批次/应完成批次 | 完整业务链记录 |

C2 可作为后续业务链评价的主要结果。若它参与成熟度定义，则不能再作为完全独立的外部验证指标。

### 4.2 业务覆盖约束下的指标筛选

定义：

\[
A_{gi}=
\begin{cases}
1,&\text{指标 }i\text{能够直接衡量需求 }g,\\
0,&\text{否则},
\end{cases}
\qquad z_i\in\{0,1\}.
\]

设 \(c_i\) 为采集和维护成本，筛选模型为：

\[
\min_z\sum_i c_i z_i
\]

约束为：

\[
\sum_iA_{gi}z_i\geq1,\qquad \forall g\in\mathcal G,
\]

\[
z_i=1,\qquad i\in\mathcal I_{\mathrm{mandatory}}.
\]

强制集合包含适用的安全、合规、恢复和重大运营风险指标。高相关性不能单独作为删除依据。只有两个指标衡量同一概念、观测方法可以替代、删除后业务覆盖和模型结论均保持稳定时，才合并或将其中一个降为低频监测指标。

### 4.3 两项现实失真因素与修正

| 现实因素 | 失真 | 修正策略 |
|---|---|---|
| 公开资料偏向大型或数字化程度高的港口 | 小港口无法采集，设备先进程度被误当作成熟度 | 标记资料的规模、年份和业务范围；以业务能力定义指标 |
| 低频高后果风险在历史样本中变异较小 | 安全、恢复等指标可能被误删 | 设置强制保留集合，并结合事故链和合规要求判断 |

### 4.4 专属检验：指标集合稳定性检验

逐类移除一类资料、一个专家组或一组试点样本后重新筛选，计算：

\[
\operatorname{Coverage}
=\frac{\text{仍被覆盖的业务需求数}}{|\mathcal G|},
\]

\[
J(S_a,S_b)=\frac{|S_a\cap S_b|}{|S_a\cup S_b|}.
\]

检验重点是业务需求是否仍被覆盖、强制指标是否保留，以及变化是否只发生在含义相近的替代指标之间。

## 5. 数据采集设计

### 5.1 统一数据结构

每条原始记录至少包含：

\[
(\text{记录编号、业务关联编号、业务单元、事件时间、录入时间、字段、来源、质量标记}).
\]

事件时间用于确定业务发生期，录入时间用于发现迟报。系统之间应使用统一业务关联编号；不能唯一匹配时保留匹配状态和歧义。

| 数据类别 | 原始字段 | 采集方式 |
|---|---|---|
| 人员 | 匿名人员编号、岗位、任务、结果、考核时间 | 分层实操测试与系统提取 |
| 培训 | 课程、日期、学时、前测、后测、延后测试 | 培训系统与跟踪测试 |
| 技术 | 服务时段、故障起止、错误码、影响范围 | 自动日志和故障复盘 |
| 数据交换 | 逻辑交易编号、源和目标、发送与接收时间 | 交易级日志 |
| 流程治理 | 数据资产、责任人、元数据、权限、审查日期 | 目录提取与抽样审计 |
| 业务链 | 批次编号、环节时间、异常、交接结果 | 端到端事件记录 |
| 项目 | 项目编号、投入、工时、上线时间、范围 | 项目台账 |
| 外部条件 | 吞吐量、货种、班次、天气、任务复杂度 | 运营和外部记录 |

### 5.2 分层抽样

系统日志在可行时全量采集，实操测试和人工审计按岗位、部门、班次、业务类型及负荷水平分层。

设第 \(h\) 层总体规模为 \(N_h\)，样本量为 \(n_h\)，合格数为 \(y_h\)：

\[
\widehat p=\sum_hW_h\widehat p_h,
\qquad W_h=\frac{N_h}{\sum_hN_h},
\qquad \widehat p_h=\frac{y_h}{n_h}.
\]

在层内简单随机抽样近似下：

\[
\widehat{\operatorname{Var}}(\widehat p)
=\sum_hW_h^2\left(1-\frac{n_h}{N_h}\right)\frac{s_h^2}{n_h}.
\]

若记录按人员、船次或班次聚集，应采用聚类稳健方差，避免把同一对象的重复观测视为独立样本。

在预算 \(C\) 下，样本配置可表示为：

\[
\min_{\{n_h\}}
\sum_hW_h^2\left(1-\frac{n_h}{N_h}\right)\frac{S_h^2}{n_h}
\]

满足：

\[
\sum_hc_hn_h\leq C,
\qquad n_h^{\min}\leq n_h\leq N_h.
\]

连续近似为：

\[
n_h\propto\frac{N_hS_h}{\sqrt{c_h}}.
\]

其中 \(S_h\) 和 \(c_h\) 由试采数据和实际工时估计。

### 5.3 两项现实失真因素与修正

| 现实因素 | 失真 | 修正策略 |
|---|---|---|
| 岗位和班次响应率不同 | 高响应群体被过度代表 | 分层记录响应情况；必要时进行响应权重调整和未响应敏感性分析 |
| 企业保密限制导致不能共享明细 | 外部团队无法审计指标来源 | 企业内部计算匿名汇总，保留内部审计链和来源版本 |

### 5.4 专属检验：采集复核

独立抽取复核样本，与原始凭据对照，检查字段准确率、计时误差、匹配失败率及抽样覆盖。复核样本不得用于调整同一版采集规则后再作为独立验证。

## 6. 数据处理

数据采用三层结构：

\[
D_{\mathrm{raw}}\rightarrow D_{\mathrm{clean}}\rightarrow D_{\mathrm{analysis}}.
\]

原始层永久保留接收记录；清洗层保存每次修改、隔离或匹配及其理由；分析层生成统一口径的指标输入。

### 6.1 时间划分与防止数据泄漏

时序数据按先后划分训练、验证和测试区间。缺失填补参数、异常阈值、标准化边界、滞后结构和模型参数只能利用训练区间估计。测试期只用于最终检验。

### 6.2 口径、单位和时间统一

- 统一时区和时间格式，检查系统时钟漂移。
- 统一货币基期、成本单位和计量单位。
- 区分船次、箱次、逻辑交易和重试事件。
- 统一岗位、业务类型、资产类别和错误码映射。
- 保存规则生效日期，避免新旧口径混用。

负延迟不能自动改为零。应先判断是时钟不同步、事件顺序错误还是业务预处理。

### 6.3 去重和跨系统关联

保留一次业务交付中的所有技术尝试，但按一个逻辑交易计算业务成功率。确定性业务编号优先；概率匹配需保存候选匹配、匹配置信度和未匹配状态。

### 6.4 缺失数据

区分不适用、日志丢失、迟报和业务尚未完成。对于应检查的 \(N\) 项，已知合格 \(y\) 项、未知 \(m\) 项，在不假设缺失机制时：

\[
p\in\left[\frac{y}{N},\frac{y+m}{N}\right].
\]

缺失机制有依据时可采用多重插补，并把插补不确定性传递到后续模型。人才到岗、工单关闭等未结束事件作为右删失记录处理。

### 6.5 异常值

异常分为逻辑错误、记录错误和真实极端事件。逻辑和记录错误经核验后修正或隔离；真实故障、超长延迟和重大安全事件必须保留。分位数或中位数绝对偏差只用于标记，不用于自动删除。

### 6.6 业务暴露量与结构调整

按适用业务量计算错误率：

\[
r_{bt}=\frac{\text{错误数量}_{bt}}{\text{适用业务数量}_{bt}}.
\]

为了比较业务结构不同的单位，使用固定参考结构：

\[
q_{bt}^{\mathrm{std}}=\sum_h\pi_h^{\mathrm{ref}}q_{bht}.
\]

同时报告实际结构下的表现和参考结构下的标准化表现。

### 6.7 标准化

原始业务单位应保留。后续模型确需统一尺度时，对正向指标使用：

\[
s_{it}=\operatorname{clip}\left(\frac{x_{it}-L_i}{U_i-L_i},0,1\right),
\]

负向指标反向处理。\(L_i,U_i\) 必须来源于适用要求、经核验的行业基准或仅使用训练数据确定的规则。超出边界的原始值仍保留。

### 6.8 两项现实失真因素与修正

| 现实因素 | 失真 | 修正策略 |
|---|---|---|
| 故障期间更容易漏记，清洗算法又倾向删除极端记录 | 风险被系统性低估 | 使用独立核验和缺失边界，保留经确认的真实极端事件 |
| 部门业务量和结构不同 | 高负荷部门被误判为能力差 | 使用暴露量、分层分析和固定参考结构标准化 |

### 6.9 专属检验：数据处理审计

进行四项检查：记录守恒、人工复核、处理方案敏感性和数据泄漏检查。若不同合理处理方案会改变成熟度等级或投资方案，则把相关字段列为优先补采对象。

## 7. KPI 与含滞后效应的时序量化

每个 KPI 输出估计值、有效样本量、未知数量、统计窗口和不确定性。

持续表现指标可表示为：

\[
\widetilde q_{it}
=\frac{\sum_{\ell=0}^{L_i}\rho_i^\ell y_{i,t-\ell}}
{\sum_{\ell=0}^{L_i}\rho_i^\ell n_{i,t-\ell}},
\qquad 0<\rho_i\leq1.
\]

其中 \(y_{it}\) 为合格数量，\(n_{it}\) 为有效观测数量。该式用于量化近期和历史表现，不单独证明培训或整改的因果效果。

行动的延迟关联可写成：

\[
Y_t\sim\operatorname{Binomial}(n_t,p_t),
\]

\[
\operatorname{logit}(p_t)
=\alpha+\beta\sum_{\ell=0}^{L}w_\ell u_{t-\ell}+\gamma^\top c_t,
\]

\[
w_\ell\geq0,\qquad\sum_{\ell=0}^{L}w_\ell=1.
\]

\(u_t\) 为培训、系统上线或治理行动量，\(c_t\) 为业务量、任务难度、岗位结构和季节因素。滞后范围由实施周期、文献和试点跟踪共同约束。

若后续能力状态模型已经包含滞后结构，前端应交付原始时序和行动日期，避免对同一滞后效应重复处理。

## 8. 核心模型一：含滞后效应的能力状态估计模型

### 8.1 目标

估计人员、技术和流程三个维度随时间变化的潜在能力，并判断培训、系统改造和治理投入何时开始产生可观测效果。

设 \(a_{dt}\in(0,1)\) 为维度 \(d\) 在时期 \(t\) 的能力状态，通过潜变量 \(z_{dt}\) 表示：

\[
a_{dt}=\frac{1}{1+e^{-z_{dt}}}.
\]

状态演化方程为：

\[
z_{dt}
=\phi_dz_{d,t-1}
+(1-\phi_d)\mu_d
+\sum_r\beta_{dr}\widetilde u_{rt}
+\gamma_d^\top c_t
+\eta_{dt},
\]

其中：

- \(\phi_d\)：能力延续性；
- \(\mu_d\)：长期基准状态；
- \(\widetilde u_{rt}\)：行动 \(r\) 的滞后有效量；
- \(c_t\)：业务量、复杂度、季节和人员结构等控制变量；
- \(\eta_{dt}\)：状态扰动。

滞后有效量为：

\[
\widetilde u_{rt}
=\frac{\sum_{\ell=0}^{L_r}\rho_r^\ell u_{r,t-\ell}}
{\sum_{\ell=0}^{L_r}\rho_r^\ell},
\qquad 0<\rho_r<1.
\]

若证据表明行动经过若干期后才开始生效，可加入起效延迟 \(d_r\)：

\[
\widetilde u_{rt}
=\frac{\sum_{\ell=d_r}^{L_r}\rho_r^{\ell-d_r}u_{r,t-\ell}}
{\sum_{\ell=d_r}^{L_r}\rho_r^{\ell-d_r}}.
\]

### 8.2 观测方程

不同类型指标采用与其分布相符的观测方程。比例指标：

\[
Y_{it}\sim\operatorname{Binomial}(N_{it},p_{it}),
\]

\[
\operatorname{logit}(p_{it})
=\alpha_i+\lambda_i z_{d(i),t}+\theta_i^\top c_t.
\]

正值时长指标可用对数正态分布：

\[
\log X_{it}\sim
\mathcal N(\alpha_i-\lambda_i z_{d(i),t}+\theta_i^\top c_t,\sigma_i^2).
\]

负号表示能力提高通常会降低时长。计数指标可采用带暴露量的 Poisson 或负二项模型：

\[
Y_{it}\sim\operatorname{NegBin}(\nu_{it},\kappa_i),
\]

\[
\log\nu_{it}=\log E_{it}+\alpha_i-\lambda_i z_{d(i),t}+\theta_i^\top c_t.
\]

\(E_{it}\) 为交易量、运行时间等暴露量。

### 8.3 模型识别与估计

每个潜在维度选择一个业务含义明确、测量稳定的锚定指标，固定其载荷方向和尺度，避免 \(z_{dt}\) 与 \(\lambda_i\) 任意缩放。参数可通过状态空间最大似然、扩展 Kalman 滤波、粒子滤波或贝叶斯方法估计，具体选择取决于样本量和非线性程度。

模型输出包括：

\[
(\widehat a_{Pt},\widehat a_{Tt},\widehat a_{Rt}),
\]

每项能力的区间估计、变化趋势和行动的滞后响应。

### 8.4 两项现实失真因素与修正

| 现实因素 | 失真 | 修正策略 |
|---|---|---|
| 培训或技术投入存在生效延迟，同时港口有旺淡季 | 把尚未生效的投入判断为无效，或把淡季改善归功于投入 | 设置分布滞后；控制吞吐量、季节、任务难度和岗位结构 |
| 日志漏报、问卷自报偏差和同源指标相关 | 记录完整的部门反而显得问题更多，重复信息导致过度自信 | 独立抽查估计漏报；优先使用行为记录；对同源观测设置相关误差并扩大区间 |

### 8.5 专属检验：滚动时间外预测

按时间滚动，用前 \(t\) 期估计能力并预测 \(t+1\) 期尚未使用的实操测试、审计结果和技术表现。比较无滞后与含滞后模型的预测误差、概率校准、区间覆盖率和残差自相关。

此外进行潜在状态恢复实验：使用已知能力轨迹生成情景数据，检验模型能否恢复状态、转折点和滞后长度。模型通过模拟恢复不等于已经验证 ICM 的真实能力。

## 9. 核心模型二：基于端到端业务链可靠性的成熟度评价模型

### 9.1 目标

评价人员、技术和流程能力能否共同保证数据从产生、传输、核验到业务决策的全过程可靠运行。

代表性业务链包括：

\[
\text{船舶到港信息}
\rightarrow\text{舱单与海关核对}
\rightarrow\text{集装箱位置确认}
\rightarrow\text{堆场安排}
\rightarrow\text{卡车或铁路交接}.
\]

对业务链 \(k\) 定义成功事件：在规定时限内完成必需数据交接，且没有影响业务的重大数据错误。

### 9.2 业务链成功概率

设模型一输出的人员、技术和流程能力为 \(a_{Pt},a_{Tt},a_{Rt}\)。业务链成功概率为：

\[
\operatorname{logit}(p_{kt})
=b_{0k}
+\sum_db_{kd}a_{dt}
+\sum_{d<e}h_{kde}a_{dt}a_{et}
+\xi_k^\top c_t.
\]

交互项反映系统协同，例如员工技能只有在工具可用和流程明确时才能充分转化为业务效果。只保留有业务机制依据的交互项，并检查模型在有效范围内满足基本单调性。

### 9.3 参考业务结构标准化

实际成功率会受到吞吐量、货种、班次和任务难度影响。为实现跨时期和跨港口比较，将业务条件固定为有明确来源的参考情景：

\[
p_{kt}^{\mathrm{ref}}
=p_k(a_t,c_k^{\mathrm{ref}}).
\]

综合成熟度为：

\[
M_t=100\sum_k\omega_kp_{kt}^{\mathrm{ref}},
\qquad \sum_k\omega_k=1.
\]

业务链权重由参考业务量、失败损失和服务承诺确定。若目标强调客户体验，可增加客户直接使用的数据链，但必须记录权重来源。

### 9.4 等级和否决门槛

成熟度分数与等级不能只采用等宽切分。等级 \(L_t\) 同时满足概率区间和制度条件：

\[
L_t=\max\{\ell:M_t\geq\tau_\ell,\ H_{m,t}=1\ \forall m\in\mathcal H_\ell\}.
\]

\(\tau_\ell\) 是经业务验证的等级阈值，\(\mathcal H_\ell\) 是进入该等级必须满足的安全、恢复、责任和治理条件。若比赛阶段没有证据确定阈值，则展示连续分数和能力画像，并把等级边界列为待校准项。

### 9.5 两项现实失真因素与修正

| 现实因素 | 失真 | 修正策略 |
|---|---|---|
| 多条业务链共享平台、网络或权限服务 | 独立假设会低估共同故障，使可靠性虚高 | 优先使用端到端记录；显式加入共享系统状态或共因随机效应 |
| 港口规模、货种和任务难度不同 | 简单业务较多的单位看起来更成熟 | 控制业务结构，在固定参考条件下比较，并同时报告实际表现 |

### 9.6 专属检验：业务概率校准

使用未参与拟合的完整业务批次，比较预测成功概率与实际成功频率，报告 Brier 分数、对数损失和校准曲线。再进行跨部门或跨港区留出验证。

使用历史或模拟的共享平台故障进行压力测试，检查多条业务链是否同步下降。若模型在正常时期校准良好但无法反映共因故障，应增加共享风险项，而不是只调整总分权重。

## 10. 核心模型三：具有边际收益衰减的稳健资源优化模型

### 10.1 目标

在预算、人力、工期、项目依赖、安全和运营连续性约束下，决定哪些项目实施、各投入多少以及何时实施。

候选项目可以包括数据目录、统一数据标准、跨系统集成、员工培训、数据人员招聘、外部技术服务、灾备改造、安全审计和实时质量监控。

设：

- \(x_{jt}\geq0\)：项目 \(j\) 在时期 \(t\) 的投入；
- \(y_j\in\{0,1\}\)：是否启动项目；
- \(E_{jt}\)：考虑滞后后的累计有效投入；
- \(g_j(E)\)：项目带来的能力改善。

### 10.2 投入滞后与边际收益递减

有效投入为：

\[
E_{jt}=\sum_{\tau\leq t}q_{j,t-\tau}x_{j\tau},
\qquad q_{j\ell}\geq0.
\]

边际收益递减函数为：

\[
g_j(E)=G_j(1-e^{-k_jE}),
\]

其中：

\[
g_j'(E)=G_jk_je^{-k_jE}>0,
\]

\[
g_j''(E)=-G_jk_j^2e^{-k_jE}<0.
\]

\(G_j\) 是规划期内可实现的最大改善，\(k_j\) 是投入转化速度。若数据不支持指数形式，可使用由试点数据校准的分段线性凹函数。

能力更新为：

\[
a_{d,t+1}(x)
=\operatorname{clip}\left(
a_{dt}+\sum_jm_{jd}g_j(E_{jt}),0,1
\right),
\]

其中 \(m_{jd}\) 描述项目对各能力维度的作用比例，来源于项目设计、试点或可比项目。

更新后的能力进入模型二，得到：

\[
p_{kt}(x)=p_k(a_t(x),c_t).
\]

### 10.3 目标函数

将收益统一为预期避免损失与服务收益：

\[
\max_x
\sum_{t,k}
\frac{V_{kt}L_{kt}[p_{kt}(x)-p_{kt}(0)]}{(1+r)^t}
-\sum_{t,j}\frac{C_{jt}(x_{jt})+F_jy_j}{(1+r)^t}.
\]

其中：

- \(V_{kt}\)：业务量；
- \(L_{kt}\)：一次失败的预期损失；
- \(C_{jt}\)：可变成本；
- \(F_j\)：项目固定启动成本；
- \(r\)：折现率。

无法可靠货币化的安全、隐私和最低服务要求作为约束，不用任意权重与货币收益相加。

### 10.4 约束条件

分期预算：

\[
\sum_j[C_{jt}(x_{jt})+F_{jt}y_j]\leq B_t,\qquad\forall t.
\]

人员容量：

\[
\sum_jh_{jqt}x_{jt}\leq H_{qt},\qquad\forall q,t.
\]

启动门槛：

\[
\underline x_jy_j\leq\sum_tx_{jt}\leq\overline x_jy_j.
\]

项目依赖：若项目 \(a\) 依赖项目 \(b\)，则

\[
y_a\leq y_b.
\]

运营中断：

\[
\sum_jd_{jt}y_j\leq D_t^{\max}.
\]

最低安全和服务要求：

\[
p_{kt}(x)\geq\underline p_k,
\qquad
a_{dt}(x)\geq\underline a_d
\]

仅在这些阈值具有合同、标准或管理决策依据时使用。

### 10.5 稳健处理

成本、工期和效果存在不确定性。构造有来源的联合情景 \(s\in\mathcal S\)，每个情景包含：

\[
\Theta_s=\{C_{jts},G_{js},k_{js},q_{j\ell s},V_{kts},L_{kts}\}.
\]

可采用最大化最坏情景净收益：

\[
\max_x\min_{s\in\mathcal S}Z(x;\Theta_s),
\]

或在预算违约概率有可靠估计时使用机会约束。若概率依据不足，优先使用透明的情景稳健方法。

### 10.6 两项现实失真因素与修正

| 现实因素 | 失真 | 修正策略 |
|---|---|---|
| 投入收益递减且部分项目有最低启动规模 | 线性模型把资金过度集中，或配置无法启动的零碎预算 | 使用凹收益函数，并设置固定成本、启动变量和最低投入 |
| 成本超支、项目延期及共享人员冲突 | 纸面组合满足总预算但无法实施 | 使用分期资源约束和成本—延期联合情景进行稳健优化 |

### 10.7 专属检验：决策回测与后悔值

使用未参与参数拟合的成本和收益情景回测方案，计算：

- 预算超限率和其他约束违背率；
- 实际实现净收益；
- 相对于情景内最优可行方案的后悔值；
- 相对于等额分配和单位成本收益排序的改进；
- 求解器最优性间隙。

另外以分段线性凹函数生成收益情景，检验指数响应假设发生偏差时项目组合是否仍然稳定。

## 11. 三个核心模型的信息传递

模型之间不是三个孤立算法，而是一条证据链：

\[
\text{原始记录}
\rightarrow\text{带误差的KPI}
\rightarrow\text{能力状态分布}
\rightarrow\text{业务链成功概率}
\rightarrow\text{项目收益分布}
\rightarrow\text{资源方案}.
\]

模型一输出能力的分布或区间，模型二应传播这种不确定性；模型二输出的业务成功概率和参数不确定性进入模型三。不能只把每一级的点估计传递下去。

可通过联合抽样实现传播：每次从前端测量误差和参数分布中抽取一组输入，依次运行三个模型，最终得到成熟度和资源方案的分布。抽样时保留指标之间和项目参数之间的相关性。

## 12. 参数确定与证据账本

每个参数记录：名称、符号、单位、业务含义、数据字段、来源、适用时期、估计方法、不确定范围、专家修订理由和版本。

| 参数类别 | 首要依据 | 其他信息的作用 |
|---|---|---|
| 指标定义与覆盖矩阵 | 赛题流程、文献和标准 | 专家核验业务适用性 |
| 抽样规模与成本 | 试采工时、系统提取成本 | 管理人员确认资源限制 |
| 滞后长度和状态参数 | 按日期记录的投入与效果时序 | 文献和专家约束合理范围 |
| 业务链系数与交互 | 端到端交易、故障记录 | 流程专家确认机制 |
| 等级门槛 | 服务要求、制度条件、结果校准 | 管理层确认决策含义 |
| 收益上限和衰减率 | 试点及可比项目投入—效果记录 | 工程专家提供容量边界 |
| 成本、损失和资源 | 采购、工时、赔付和财务数据 | 财务与运营人员复核 |

三类证据承担不同职责：标准规定边界，统计数据估计关系，专家说明机制和适用范围。三者冲突时调查口径和迁移条件，不直接无依据地取平均。

若采用概率形式，可写为：

\[
p(\theta\mid D,E,S)
\propto p(D\mid\theta)p(\theta\mid E)\mathbf1\{\theta\in\Theta_S\},
\]

其中 \(D\) 为观测数据，\(E\) 为结构化专家意见，\(\Theta_S\) 为标准允许范围。若专家已经看过同一批数据，需防止重复计算证据。

## 13. 无真实数据时的情景演示与验证

比赛阶段从原始事件开始生成数据：

\[
\text{模拟测试、交易、故障和项目记录}
\rightarrow\text{加入迟报、缺失、重复和共因故障}
\rightarrow\text{数据处理}
\rightarrow\text{KPI}
\rightarrow\text{三个模型}.
\]

至少设置七类情景：

1. 人员、技术和流程均衡发展；
2. 技术较强但治理薄弱；
3. 培训效果延迟出现；
4. 旺季负荷导致错误和延迟上升；
5. 共享系统故障影响多条业务链；
6. 投入增加但增量收益递减；
7. 日志缺失与抽样偏差加重。

验证分为两层：

- 方法恢复能力：在已知模拟真值时，采集、处理和模型能否恢复指标、状态及参数。
- 结构偏差稳健性：生成机制与拟合模型不完全一致时，成熟度和资源决策是否仍然稳定。

情景参数必须标明依据。没有资料支持的数值写成测试假设，并进行范围敏感性分析。

## 14. 持续监测协议

监测频率根据风险和变化速度设置：

| 频率 | 监测内容 |
|---|---|
| 实时或每日 | 系统可用性、接口失败、重大安全异常、关键数据缺失 |
| 每月 | 数据质量、问题闭环、培训进度、访问审批和业务链成功率 |
| 每季度 | 能力状态更新、模型校准、指标缺失和参数漂移 |
| 每半年或年度 | 全面成熟度复评、指标体系审查和资源方案更新 |

出现以下情况时触发额外复评：指标定义改变、系统架构改变、法规或合同要求改变、业务规模显著变化、预测校准恶化、连续多期越过风险阈值。

## 15. 跨规模与跨行业迁移

通用部分包括人员、技术、流程和协同结构，以及采集、处理和验证原则。需要重新校准的部分包括指标阈值、业务链、参考结构、失败损失、采集频率和资源约束。

大型港口更关注实时性、系统集成、可扩展性和共因风险；小型港口更关注关键岗位覆盖、成本和轻量化治理。成熟度衡量的是技术与业务需求的匹配程度，不是软件价格。

迁移到卡车运输公司时，可将业务链替换为订单接收、车辆调度、位置更新、预计到达、交付确认和客户反馈；核心框架保持不变，但参数必须利用运输企业自己的数据重新估计。

## 16. 论文建议结构

1. Summary Sheet：问题、方法、核心结论和实施价值。
2. Problem Restatement and Assumptions：说明 ICM 为案例公司、无真实数值数据。
3. Data and Indicator Framework：指标识别、采集、处理和数据来源。
4. Model I：能力状态估计、现实修正和专属检验。
5. Model II：业务链成熟度评价、现实修正和专属检验。
6. Model III：资源优化、边际收益递减、现实修正和专属检验。
7. Scenario Demonstration：明确标注的情景数据和结果。
8. Monitoring and Adaptation：监测协议和跨场景迁移。
9. Strengths and Limitations：证据边界、数据需求和适用条件。
10. Letter to Customers：以非技术语言说明测量、保护、审查和改进机制。

## 17. 最终交付物

完整系统应交付：

1. 指标字典；
2. 采集协议；
3. 数据处理与质量控制规则；
4. KPI 时序数据及不确定性；
5. 三个核心模型及各自专属检验；
6. 参数证据账本；
7. 情景数据生成和验证说明；
8. 持续监测与模型更新协议。

\[
\mathcal O_{ibt}
=\left(
\widehat x_{ibt},U_{ibt},n_{ibt},m_{ibt},c_{bt},
\mathrm{source}_{ibt},\mathrm{version}_i
\right),
\]

分别表示指标估计、不确定性、有效样本量、未知数量、业务条件、来源和规则版本。
